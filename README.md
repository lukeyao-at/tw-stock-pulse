# 台股脈動（tw-stock-pulse）

個人化的台股追蹤工具：自選股與持股損益、**依你的自選股過濾並判讀情緒的新聞**、
**帶理由的推薦標的**、以及價格與事件提醒。資料抓自證交所與櫃買中心的公開端點。

- 零執行期依賴 —— `npm start` 不需要 `npm install` 就能跑（只有建 CSS 才需要 devDependency）
- 樣式與圖示全部自帶，不連任何 CDN
- 後端零狀態：沒有帳號、沒有資料庫、不設 cookie。你的持股明細只存在自己的瀏覽器裡

---

## 快速開始

```bash
npm start                # http://localhost:8420
npm run offline          # 用內建樣本資料跑，完全不連外
npm test                 # 60 個單元測試
npm run check-sources    # 逐一實測每個公開來源是否還活著
```

Node 需要 18.17 以上（用到內建 `fetch` 與 `node:test`）。

### 只想先看介面

`demo/index.html` 是**單一自包含檔案**，用瀏覽器直接開就有完整介面，不需要
Node、不需要伺服器、不連任何外部網站。自選股、推薦、新聞判讀、持股損益都能
實際操作，只是數字來自 `data/` 底下的樣本資料。

它由 `npm run build:demo` 從真實原始碼組出來 —— 計分引擎、情緒判讀、新聞比對
全部直接取用 `src/`，前端也是原封不動內嵌 `public/app.js`，只用一層 fetch 攔截
把 `/api/*` 換成瀏覽器端運算。所以 demo 的行為和真的跑起來一致，改了程式碼記得
重跑一次讓它同步。

改動 `public/` 裡的樣式類別後要重建 CSS：

```bash
npm install              # 只為了 tailwindcss（devDependency）
npm run build:css        # 或 npm run watch:css 開發時持續重建
```

## 功能

### 個人化新聞
從多個財經 RSS 抓新聞，再用兩種方式跟你的自選股對起來：

1. **個股專屬 feed** —— 直接向來源要某一檔的新聞，最精準
2. **內文比對** —— 代號與公司名稱（含別名如「台積」、「TSMC」）

比對刻意做得保守，避免常見的誤判：

| 標題 | 判定 | 原因 |
|---|---|---|
| 台股 **2026** 年展望 | 不算榮科(2026) | 後面接「年」，是年份不是代號 |
| 台股攻上 **2330** 點 | 不算台積電 | 後面接「點」，是點數不是代號 |
| **中鋼構**今日漲停 | 不算中鋼(2002) | 命中位置屬於另一家公司 |
| **中鋼**盤後大單敲進 | 算中鋼(2002) | 沒有更長的公司名蓋住它 |
| 長榮航空與**長榮海運**雙漲 | 算長榮(2603) | 第二次出現不被長榮航蓋住 |

情緒判讀用「中文詞典 + 權重」而非機器學習 —— 台股新聞用語高度固定
（「上調目標價」、「外資買超」、「財測下修」），詞典的準確度足夠，而且**可解釋、
可測試、不需要任何 API key**。另外處理三件事：

- **否定翻轉**：「不看好」算利空，「不虧損」算利多
- **重疊去重**：「財測下修」不會再被「下修」加算一次
- **推測打折**：「傳砍單」的分數低於「確認砍單」；但「傳**統**封測」、「疑**慮**」
  不會被誤判成推測語氣

### 推薦標的
五個具名因子加權計分，權重隨你的風險偏好與投資目標改變：

| 因子 | 保守 | 穩健 | 積極 |
|---|---|---|---|
| 股利 | 32% | 20% | 6% |
| 價值 | 24% | 24% | 14% |
| 流動性 | 22% | 14% | 10% |
| 動能 | 4% | 20% | 44% |
| 分散度 | 18% | 22% | 26% |

設計上刻意避開幾個常見陷阱：

- **殖利率不是越高越好**。7% 附近給滿分，超過就遞減 —— 景氣循環股在獲利高點
  常出現 10%+ 的殖利率，隔年就大幅縮水，對保守型投資人是風險而不是優點
- **缺資料不等於零分**。生技股常沒有本益比（還在虧損），這種情況該因子以中性
  計分並在理由裡註明，而不是把它踢到最後
- **「主因」看的是突出程度**，不是絕對分數。持股少的時候幾乎每檔的分散度都是
  滿分，用絕對分數會讓每檔的主因都變成「分散度」，等於沒有資訊
- 每檔推薦附上**拿實際數字跟市場中位數比較**的理由，以及風險警示。不做黑箱評分
- 同一產業有數量上限，整份清單不會全是金融股

### 持股損益
費用預設用台股實務值：手續費 0.1425%（買賣各一次，可設折扣，最低 20 元）、
賣出證交稅 0.3%，算的是**真正落袋**的損益。同一檔重複買進會自動算加權平均成本。
另外顯示產業集中度，單一產業超過 40% 會提示。

### 提醒
價格門檻、單日漲跌幅、成交量放大倍數、利多／利空新聞出現、除權息與法說會倒數。

規則評估是純函式且無副作用 —— **拿不到資料時會明確標為「跳過」並說明原因，
而不是回一個看起來正常的假結果**。（例如均量基準抓不到時，量能提醒會顯示
「缺少均量基準，無法計算放大倍數」，不會拿當日量跟自己比得出恆為 1 倍的結論。）

### 重要發現：openapi 新網域 vs. www 舊網域

TWSE 的 WAF 會擋掉雲端機房來源的連線，但**只擋新版 API 網域
`openapi.twse.com.tw`，不擋舊版 `www.twse.com.tw` 網域**（搭配
`response=open_data` 或 `response=json` 參數 —— 這是政府開放資料平台
登記的正式格式，不是繞防護的取巧做法）。同一份資料（每日行情、本益比、
除權息）兩個網域都有，只是回傳格式不同：

- `openapi.twse.com.tw` → 現成的 JSON 物件陣列
- `www.twse.com.tw/exchangeReport/...?response=open_data` → **CSV**（`src/parse.js` 的 `parseCsv`）
- `www.twse.com.tw/rwd/zh/.../...?response=json` → `{ stat, fields:[...], data:[[...],...] }` **位置對應陣列**（`zipFieldsData` 攤平成物件再用 `pick()` 取值）

如果哪天連舊網域也開始被擋，或哪天新網域解封了，只要在 `src/config.js` 換
網址即可，`src/sources/twse.js` 的解析邏輯已經同時支援三種格式。

### 重要發現：Node.js 的 `fetch` 不會自動讀取 `HTTPS_PROXY`

如果你的網路環境需要透過 proxy 才能連外（常見於公司網路），要注意
**Node.js 內建的 `fetch`（底層是 undici）預設不會讀取 `HTTPS_PROXY`／
`https_proxy` 環境變數**，跟 curl、瀏覽器的行為不一樣——會直接嘗試連線
而不經過 proxy，在需要 proxy 的網路下会直接失敗。

本專案已經在 `package.json` 的所有執行腳本加上
`NODE_OPTIONS=--use-env-proxy`（Node 內建但仍屬實驗性的旗標）解決這個
問題。沒有設定 proxy 環境變數時這個旗標完全零副作用，已實測確認；如果
你直接用 `node server.js` 而不是 `npm start`，記得自己加上這個旗標。

**這些端點會改版、會限流。** 所以：

- 欄位一律用「候選名稱清單」挑選（`src/parse.js` 的 `pick`），同一份行情不管叫
  `Code`、`SecuritiesCompanyCode` 還是 `公司代號` 都吃得下
- 事件類與上櫃估值端點做成候選 URL 清單，逐一嘗試，失敗的略過
- 任何來源失敗只會讓對應欄位顯示「—」並在「設定 → 資料來源健康度」列出原因，
  不會讓整頁掛掉
- 抓取失敗時會退回上一次成功的快取（「資料稍舊」優於「整頁空白」）
- 行情全掛才退回內建樣本資料，並在畫面上明確標示
- 短時間內對同一端點打太多次會觸發暫時性限流（307，幾秒到幾十秒後自動恢復），
  不是端點掛了；正常使用頻率（估值快取 1 小時）不會遇到

要確認目前哪些來源還活著，跑 `npm run check-sources`：它會實際打每一個端點，
自動判斷 JSON／CSV／位置陣列三種格式，印出筆數與**實際回傳的欄位名稱**，
端點改版時這是最快的線索。

## 架構

```
server.js              HTTP 伺服器（node:http，四條路由，零依賴）
src/
  config.js            所有外部端點與快取秒數集中在此
  http.js              逾時、重試、瀏覽器樣 UA
  cache.js             TTL 快取 +「陳舊但可用」退回機制
  parse.js             欄位彈性挑選、民國日期、數字、RSS/Atom 解析
  universe.js          合併上市＋上櫃 → 單一股票查詢表
  match.js             新聞 ↔ 個股比對
  sentiment.js         中文利多／利空詞典判讀
  recommend.js         推薦計分引擎
  portfolio.js         持股損益與產業集中度
  alerts.js            提醒規則評估
  api.js               組合成單一 dashboard 回應
  sources/             twse / tpex / quotes / news / history
public/                單頁 UI（自帶 Tailwind CSS 與 SVG 圖示）
data/                  離線樣本資料
test/                  60 個單元測試
```

API：

| 端點 | 說明 |
|---|---|
| `POST /api/dashboard` | 主要端點。帶入個人化設定，一次回傳整個畫面的資料 |
| `GET /api/search?q=` | 個股搜尋（代號或名稱） |
| `GET /api/health` | 來源健康度與快取狀態 |

個人化資料由前端在請求裡帶上來，後端不保存 —— 所以部署是零狀態的，
我們也不必去保管別人的持股明細。

## 已知限制

誠實列出來，別把它當成它做不到的東西：

- **推薦引擎不理解景氣循環**。它看得懂「殖利率異常高要打折」，但不知道航運與
  面板是循環產業。保守型清單裡出現循環股在高點的身影是可能的，理由與警示欄
  會給你判斷依據，但引擎本身不做產業循環判斷。
- **情緒判讀是詞典法**，不理解反諷、複雜因果或長文脈絡。它處理標題很稱職，
  處理分析文章的細微語氣不行。
- **推薦與情緒都只用當日資料**，沒有技術指標、沒有歷史回測、沒有基本面趨勢。
- **公司名稱別名清單是手工維護的**（`src/match.js` 的 `ALIASES`），只涵蓋常見權值股。
  冷門股若新聞只用簡稱可能比對不到。
- **盤中即時報價目前抓不到**（MIS 端點的防護最嚴，實測持續回 502），
  所以畫面上永遠顯示收盤價、標為「收盤」而非「盤中」，不會即時跳動。
  非交易時段這本來就是正常行為，但目前連盤中也一樣，等於失去了「盤中」
  這個標籤原本要傳達的即時性。
- **產業別資料目前抓不到**（`t187ap03_L` 被 WAF 擋，找不到替代端點），
  推薦引擎對上市股票因此無法判斷分散度（該因子固定給滿分，等於不參與
  排序），上櫃股票不受影響（來源正常）。這個缺口曾經引出一個真正的
  bug：產業上限機制原本會把「不知道產業別」的標的全部當成同一個產業
  套用數量上限，導致要求 8 檔卻只拿到 2、3 檔——已修正為只對「已知
  產業」的標的套上限（見 `src/recommend.js`）。
- 不含任何下單、券商 API 或帳務整合。

### 這個專案在什麼環境下被驗證過

開發環境的對外連線一開始被組織的網路政策整個阻擋，之後政策放寬，
於 2026-09-15 完成了對真實端點的驗證：

- **已實測（真實資料）**：上市每日行情、上市本益比／殖利率／淨值比、
  上市除權息／除權息預告、上櫃行情／估值／基本資料、歷史日成交、
  新聞 RSS —— 用真實今日行情跑過 `/api/dashboard`，確認自選股報價、
  持股損益、市場漲跌統計都是用真實數字算出來的
- **已確認持續失效**：上市公司基本資料（產業別）、盤中即時報價
  （MIS）、法說會、月營收 —— 這幾支目前找不到未被擋的替代端點，
  詳見上方「資料來源」表格；系統會自動降級（該欄位顯示「—」或退回
  收盤價），不影響其他功能
- **已實測**：全部 60 個單元測試、離線模式與線上模式下的完整 App
  （headless Chromium 跑過六個分頁，零 console error）
- 驗證過程中額外修正兩個真實 bug：`normalizeCode()` 漏接 5 碼數字的
  主動式 ETF 代號（曾讓 11% 的上市證券消失）、Node `fetch` 不讀
  `HTTPS_PROXY` 導致需要 proxy 的網路環境下抓取全部失敗

跑起來後仍然建議先執行 `npm run check-sources`——你的網路環境、當下的
限流狀態都可能跟這裡的實測結果不同。

## 免責聲明

本工具僅整理公開資訊並依你設定的條件做排序與計算，**不構成投資建議**，
也不保證資料即時或正確。`data/` 下的樣本資料為模擬數值，僅供介面演示。
投資決策請自行核實資料並承擔風險。
